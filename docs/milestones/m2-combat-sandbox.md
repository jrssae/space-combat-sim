## Before you start

The M1 play-test fixes land before M2 and change code that M2 builds on. Read the code, not only the M1 doc, for:

- **Controls**: yaw on the D-pad, roll on the right stick, hold D-pad Up = target ahead (the maintainer's pad has no
  R3/L3). M2 adds no bindings; hostile-first `target_next` (T02) replaces a new button.
- **Brake**: all stop including rotation, and it turns the nose to the selected target. Read how the nose-to-target
  attitude control was built before writing `PilotSteering` (T07); reuse it if it fits.
- **Rendering**: rigid chase camera, plumes along the nozzle axes (`ThrusterVisuals`), a hull depth proxy (an inset
  opaque mesh, so transparent effects behind the hull are hidden), a reworked Starfury silhouette, GDGS sort-overflow
  and narrow-subgroup patches (`addons/gdgs/PATCHES.md`).
- **Tooling**: the console `screenshot` command and `scripts/capture.sh` (llvmpipe; GDGS falls back to Raster).

Where those fixes renamed something §15 mentions, follow the code and record the difference in the task's "As
built" notes, as M1 did.

## Scope

In:
- `raider_fighter` (Delta-V) generated by `tools/procgen` with the full asset contract plus break-up `chunks`, and a
  `raider` style.
- Raiders as real `Ship`s (same flight model and limits as the player) flown by simple `PilotBrain`s: idle, patrol a
  waypoint loop, attack runs, and patrol-then-attack. The brain interface is the seam M3's `AiPilot` implements.
- Projectile hit detection that holds at any closing speed (target-relative swept test per tick), faction rules (no
  friendly fire, no self-hits), hull points, damage, god mode wired to player damage.
- Destruction: generated explosion effect, break-up into generated debris, player death and respawn.
- Pools for every splat-bearing entity, so nothing hitches when ships spawn or die (D22).
- A minimal HUD: boresight, velocity vector, target box with hull bar, lead reticle, own hull bar, status line.
- `combat_sandbox` scenario with waves that loop and grow; free flight still available.
- Console commands and providers for all of it; new settings as schema entries.
- Control profiles: switch between saved binding sets (maintainer request; cheap because the input layer reads
  `InputMap` live).
- Generated sound effects (T12) if it fits; it can slip to M3 without blocking M2.

Out (explicitly):
- Full AI pilots: utility selection, evasion, formation, wingmen, allies, collision avoidance (M3).
- Raider carriers and the Raider Battle Wagon, as models or spawn points (M11; see the roadmap). Raiders appear
  from the pool beyond 1 km.
- Shields, subsystems, missiles or other secondary weapons, ammo, heat, energy, finite reaction mass.
- Ship-to-ship collision damage (Jolt still makes ships bounce; ram damage is M3).
- Starfury break-up chunks (the Starfury is being reworked; M3 adds chunks for allied Starfuries). The player's
  death uses the explosion and generic shards.
- Mission framework, objectives, subtitles, menus, a controls menu (M4), jumpgate arrivals (M5/M7), music, voice.
- Damage decals or scorch marks on splats, smoke trails, camera shake, kill cam, scoring beyond a kill counter.
- Splat LOD and relighting (M5 / M1.5).

### M2-T01 Combat maths (pure)

- Goal: the pure foundations every combat task uses (§15.4, §15.5, §15.8).
- Agent: **Sonnet**. Closed-form maths whose formulas and test vectors are given here.
- Files: `src/combat/{factions,hull_health,sweep_math,hit_shape,hit_info,intercept_math}.gd`,
  `tests/unit/{test_factions,test_hull_health,test_sweep_math,test_hit_shape,test_intercept_math}.gd`.
- Notes:
  - `Factions`: `EARTH_ALLIANCE = &"earth_alliance"`, `RAIDERS = &"raiders"`, `NEUTRAL = &"neutral"`;
    `enum Relation { FRIENDLY, NEUTRAL, HOSTILE }`; `relation(a, b)`: same faction → FRIENDLY; either neutral or
    unknown → NEUTRAL; earth_alliance vs raiders → HOSTILE. `is_hostile(a, b)`. `hud_color(relation) -> Color`:
    hostile (1.0, 0.35, 0.25), neutral/unknown **yellow** (1.0, 0.85, 0.25), friendly (0.45, 0.7, 1.0)
    (maintainer answer Q4). The HUD's own line work stays green (0.55, 1.0, 0.6).
  - `HullHealth`: `max_hp`, `hp`, `apply(amount) -> float` (applied; negative or NaN amounts apply 0), `destroyed`,
    `destroyed_now` (true only after the `apply` that crossed zero), `restore()`, `fraction()`.
  - `SweepMath` (static; every function returns the entry fraction t in [0, 1], 0 when the start is inside, -1 for
    no hit; intermediate maths in 64-bit `float`):
    - `segment_sphere(a, b, c, r)`: d = b - a, m = a - c; C = m·m - r² ≤ 0 → 0; A = d·d ≈ 0 → -1;
      B = 2 m·d; disc = B² - 4AC < 0 → -1; t = (-B - √disc) / 2A, valid in [0, 1].
    - `segment_box(a, b, half_extents, inflate)`: slab test against the axis-aligned box `half_extents + inflate`
      in the box's own frame.
    - `segment_capsule(a, b, half_segment, radius)`: axis along local +Y from -h to +h (Godot's `CapsuleShape3D`
      convention; h = height / 2 - radius). Inside if the distance from a to the axis segment ≤ radius. Otherwise
      the minimum of the infinite-cylinder entry (quadratic in x and z) where |y| ≤ h, and `segment_sphere` against
      the two end spheres.
  - `HitShape`: `BOX` or `CAPSULE`, `transform` (body frame), sizes; `static from_collision(entry)` from one
    `Hardpoints.collision` entry (it already holds a `Shape3D` and the transform that lays a capsule's axis on
    local Y); `sweep(a_body, b_body, inflate) -> float` (segment into shape space via `transform.affine_inverse()`,
    then `SweepMath`); `extent_radius()` (distance from the body origin to the farthest point); `contains(p,
    inflate)` for tests.
  - `HitInfo`: `target_id`, `shooter_id`, `faction`, `damage`, `point` (World-local), `normal` (best effort: the
    reversed relative direction is acceptable), `relative_speed_mps`, `applied` (set by the Damageable).
  - `InterceptMath.solve(shooter_pos, shooter_vel, target_pos, target_vel, bolt_speed, max_time) -> Dictionary`
    `{ok, t, aim_dir, lead_point}`: r = p_t - p_s, u = v_t - v_s (the bolt inherits the shooter's velocity, so
    it travels at `bolt_speed` relative to the shooter); (u·u - s²) t² + 2 (r·u) t + r·r = 0; smallest positive
    root (linear case when |u·u - s²| is tiny); `aim_dir = (r + u t) / (s t)`; `lead_point = p_t + u t`
    (World-local, the point to put under the reticle); `ok` false without a positive root or when t > max_time.
    Differences in 64-bit as in `TargetingSystem._offset64`.
- Tests: the AC1 cases, plus sphere: a = (-10, 0, 0), b = (10, 0, 0), r = 1 → t = 0.45; grazing at y = 1 →
  t = 0.5 ± 1e-6; y = 1.001 → -1. Box half (1, 2, 3), inflate 0.1, along x at y = z = 0 → 0.445. Capsule h = 1.5,
  r = 0.5: along x at y = 0 → 0.475; along x at y = 1.8 → 0.48 (end sphere); along y at x = z = 0 → 0.4; parallel at
  x = 0.6 → -1. Brute force: sample 10 000 points per segment; classifications agree except within 1e-4 of
  tangency. Intercept: static target at 1 km, s = 400 → t = 2.5, aim (0, 0, -1); crossing u = (100, 0, 0) → t =
  1000 / √(400² - 100²); receding faster than s → no solution.
- Done when: AC1 passes; nothing in these files touches the scene tree.
- Verify: GUT unit suite.

### M2-T02 Multi-ship readiness

- Goal: more than one ship can exist, and player and AI ships are built and commanded through the same path.
- Agent: **Sonnet**. A mechanical refactor with explicit invariants; the M1 suite guards behaviour.
- Files: `src/ship/{ship,ship_spec}.gd`, `src/targeting/{targetable,targeting_controller,targeting_system}.gd`,
  `src/weapons/{pulse_cannon,pulse_cannon_gate,projectile,weapon_spec}.gd`, `src/ship/thruster_visuals.gd` (glow
  tint), `src/game/{combatant,ship_assembly,main}.gd`, `assets/weapons/pulse_cannon_ef.tres`,
  `assets/ships/starfury_aurora.tres`, `tests/unit/{test_pulse_cannon_gate,test_targeting_system}.gd` (extend),
  `tests/integration/{test_multi_ship,test_weapons}.gd`.
- Notes:
  - Console ownership (D27): `Ship.console_owner := false`, set before the ship enters the tree (ShipAssembly sets it
    for the player). Only then does the ship register `ship` and `assist`, and it passes the flag on:
    `TargetingController.setup(body, register_console)` and `PulseCannon.setup(..., register_console)` register
    there instead of in `_ready`. Unregistering stays in `_exit_tree`.
  - `WeaponSpec` (Resource): `muzzle_speed_mps` 400, `shot_interval_s` 0.25 (per bolt; LINKED fires every interval ×
    muzzles), `damage` 10, `lifetime_s` 4, `hit_radius_m` 0.25, `bolt_material`, `bolt_length_m` 1.5,
    `bolt_radius_m` 0.05, `bolt_color`. `ShipSpec` gains `weapon: WeaponSpec`, `hull_max` (300) and
    `engine_glow_color` (today's glow colour). The Starfury's values reproduce M1 exactly.
  - `PulseCannonGate`: `muzzle_count` (≥ 1, default 2) and `interval_s` from the spec. ALTERNATING cycles muzzles
    0..n-1 one per interval; LINKED fires all every interval × n; the cooldown carry-over rule stays. `PulseCannon.setup
    (body, muzzles, projectiles_parent, weapon, register_console := false)` takes any muzzle count ≥ 1; bolts take
    lifetime and look from the spec.
  - `Combatant` (RefCounted handle: `ship`, `cannon`, `thrusters`, `targetable`, later `damageable` and `driver`,
    `faction`, `display_name`, `is_player`) with `apply_commands(flight, combat)` = `ship.set_flight_command`,
    `ship.set_combat_command`, `cannon.set_combat_command`. `ShipAssembly.build(spec, world, projectiles_parent,
    opts) -> Combatant` with opts `faction`, `display_name`, `console_owner`, `force_assist` (AI ships: always on).
    It creates the ship (`Ship.create`), `ThrusterVisuals` (tinted by `engine_glow_color`), `PulseCannon` and a
    `Targetable` child. The player gets one too (`earth_alliance`), so raiders can target it. The caller spawns
